# Як робити внесок

Paintbox відкритий для змін: виправлення, переклади, нові ефекти й
інструменти. Нижче — правила архітектури й стилю, яких тримається код.
Будова програми — [docs/architecture.md](docs/architecture.md), збірка й
запуск — [docs/building.md](docs/building.md), поведінка інструментів і
клавіш — [docs/behaviour.md](docs/behaviour.md). Код і документи —
англійською (коментарі) та українською (документи в `docs/`); пропозиції
англійською теж приймаються.

Оболонка редактора — програма на Flutter (`app/`) над ядром
`paintbox_core` (Rust, `crates/paintbox_core`). Melos-монорепо пакетів
**tools ← logic ← ui** з кореневим `app/lib/` як композиційним коренем.

Надсилаючи зміну, ви погоджуєтесь, що вона поширюється на умовах
ліцензії проєкту — GNU GPL v3 або новішої ([LICENSE](LICENSE)).

## Шари і межі

- `packages_tools/`: механізми без фіч. `core` — `Failure`, `AppLog`,
  `injector`, `EventBusService`; `paint_bridge` — ядро через
  flutter_rust_bridge (згенеровані прив'язки, cargokit). Шар імпортує
  лише з шарів ліворуч від себе.
- `packages_logic/paint_logic`: відкриті зображення, налаштування,
  нещодавні файли, буфер обміну, файлові діалоги, вид полотна. Нічого в
  logic не читає `injector`: залежності — через конструктори.
- `packages_ui/`: `app_ui` (тема, токени, скло, тости, діалоги,
  `ActionListener`, gen-l10n), `editor_ui` (сторінка, компоненти,
  віджети, блоки).
- Логіка, що не залежить від тулкіта (інструменти, жести, команди з
  доступністю й клавішами, діалоги з переглядом, цикли клавіш), живе в
  ядрі. Dart її не повторює: міст лише перекладає. Нова така логіка —
  спершу в `paintbox_core`, потім у міст.
- Міст (`packages_tools/paint_bridge/rust`) тонкий: перетворення типів,
  збої ядра в `PaintError`, нічого не панікує через межу. Після зміни
  `rust/src/api` — `melos run gen:bridge`.
- Ядро не залежить від жодного тулкіта інтерфейсу: його можна вбудувати
  в іншу оболонку.

## Збої

- Кидаються й ловляться лише `Failure` (sealed, `core`). Збій ядра стає
  `PaintFailure` (зі стабільним кодом ядра) або `StorageFailure` в
  одному місці — `PaintCall`. Кожен виклик ядра з logic іде через
  `PaintCall.run` / `runAsync`.
- Кожен блок обробляє гілку збою: `AppLog.failure` плюс
  `ShowFailureAction` на шині. Проковтнутий мовчки збій — це баг.

## Стан екрана

- Блок — машина станів екрана: один вхід `add(event)`. Стани sealed,
  незмінні, з `copyWith`; одна підкласа на взаємовиключну ситуацію.
  Умови, які перевіряє екран, — геттери стану (`canRun`, `canUndo`), а не
  обчислення у віджетах.
- Кожна дія користувача — `XEvent`. Одноразові наслідки (питання, тости,
  змінені плитки полотна) — `XAction` на `EventBusService`, які слухає
  `ActionListener`, а не прапорці в станах.
- Сторінка (`Page`) робить DI через `injector` і володіє життєвим
  циклом; компонент (`Component`) тримає `BlocBuilder`/`BlocSelector` і
  `ActionListener`; віджет (`Widget`) не знає блоків: усе показане —
  передане, усе зроблене — зворотний виклик.

## Типізація і назви

- Строгий аналіз (`strict-casts`, `strict-inference`,
  `strict-raw-types`); nullable лише там, де відсутність — значення.
  Без глобальних функцій і змінних (статики класів чи розширення);
  винятки — `main`, `bootstrap`, `configureDependencies`, `injector`.
- Суфікси обов'язкові: Page / Component / Widget / Bloc / Event / State /
  Action / Repository / Service / Storage / JsonMapper. Клас на файл,
  назва файлу — назва класу (дрібні приватні віджети — поруч із
  власником). Назви Flutter — за конвенціями Flutter.
- `context` — лише `BuildContext`. Коментар каже чому, а не що.

## Інтерфейс

- Вигляд — скло замість Material за замовчуванням: поверхні через
  `GlassPanel`, межі — `Hairline` і токени, ряди — `GlassTap`, одна
  гарнітура Manrope, відступи лише зі шкали `Space`, скруглення — з
  `Radii`, рух 160–220 мс (`Motion`). Кольори — з `AppTokens` і схеми, не
  `Colors.red`. Темна й світла теми.
- Однаковий вигляд на всіх платформах: власна верстка; системні лише
  вікно і його панель.
- Стрибків розміру немає: те, що росте, анімується (`AnimatedSize`).
- Наслідки — тости (`AppToastService`), питання — `AppDialogs`, помилки
  форм — поруч із полем.
- Кожне слово інтерфейсу — з gen-l10n `app_ui` (`melos run gen:l10n`),
  українська — шаблон; ключі додаються в обидва arb. Слова ідентифікаторів
  ядра (команди, інструменти, параметри) — через `PaintWords` з
  відкатом на англійську назву ядра.

## Перевірка

- `melos run analyze` (fatal-infos, має бути чисто), `melos run
  format:check`, `melos run test` (тести вантажать міст, зібраний
  `cargo build -p paintbox_bridge` у корені репозиторію), `flutter build windows`.
  `tools/check.ps1` робить це разом (`-Build` — із збіркою).
- Візуальну зміну перевіряють знімками: `paintbox --screenshot=<png>`
  (сцени — `docs/building.md`).
